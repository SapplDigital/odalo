# Language-switch flash - completion, REVISED (2026-10-30), Sonnet 5.5 only; no Git writes; owner acceptance NOT claimed
## Root cause (unchanged, measured)
Language links are correct (same preview origin, `/es/ /de/ /en/`). The home server HTML is the plain readable stack (the no-JS/failure fallback); it painted on the new page before the mosaic module + `document.fonts.ready` mounted, then jumped to the mosaic ("another site"). Real-browser CDP frame capture, 150 ms latency + 4x CPU: stack frame at ~450 ms (desktop) / ~460 ms (phone). Evidence: `docs/review/language-flash/before/`.
## First attempt REJECTED by planner and removed
Hiding header/main/footer (4 s CSS backstop) swapped the stack flash for a blank navy window (up to 1.8 s). Not kept: no `hm-done`/`hm-backstop`/visibility rule remains in source or package (reviewer-grepped). Superseded deploy `6ae3a2a20124c575cb8e5638` (interim, not accepted).
## Actual solution
1. `astro.config.mjs` integration `homeMosaicFirstPaint` (`astro:build:done`): moves the already-bundled HomeMosaic module script from `<main>` into `<head>` as `<script type="module" src=... blocking="render">`. Chromium then keeps showing the PREVIOUS page until the mosaic is mounted and can paint (browser-native hold, no timer, no screenshot, no spinner; it ends when the script has run or failed to load - same class of blocking as the stylesheet). Only the 3 home pages; dev server unaffected; if the tag is not found nothing changes.
2. `HomeMosaic.astro`: mounts synchronously, no `fonts.ready` wait; `runtime.js` `window.__hmFonts` (called on `document.fonts.ready`) re-fits if text overflows, otherwise re-measures; fit guards untouched.
3. `Header.astro`: the nav panel carries `hidden` in the server HTML (CSS keeps it visible on desktop and `.no-js`). Needed because, once the stack no longer hides the header, phone frames showed the menu panel OPEN until the header script ran (latent bug).
4. `tests/language-flash.spec.ts` rewritten (8 tests): blocking attribute in head only on home EN/ES/DE; panel hidden in HTML; JS disabled stack + links visible (desktop+phone); script aborted -> stack readable at once; late fonts (woff2 delayed 1.2 s) mosaic already live, no clipping after (desktop+phone); language links same origin/locale. `playwright.home.config.ts` includes it.
## Fallbacks
No JS: nothing runs/blocks, stack and menu links visible at once. Script fails to load: block ends, stack readable immediately (tested). Browsers ignoring `blocking` (e.g. some Firefox/Safari): degrade to the previous readable stack flash (not blank). Direct cold first load: no previous page exists, so the browser waits for CSS + the small same-origin script (blank white briefly) - inherent to any non-static solution; no further hide. Reduced motion unaffected.
